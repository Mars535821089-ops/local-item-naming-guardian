# 自动规范化设计

用户已明确要求实现自动规范化；沿用既有安全优先和系统原名例外。

目标：从仅观察升级为自动执行。自动规范用户自己拥有、用途已核实的 LaunchAgents；每次巡检恢复同一身份的名称回退。支持完整用途登记的新建项。第三方签名应用、系统权限身份、用途不明或管理员文件不强改。

方案：不用通用 AI 猜用途或改系统数据库，使用私有证据规则绑定启动标签、配置路径、参数摘要、真实目标和源码摘要。生成独立签名用途包装器，仅替换启动入口身份字段；其余配置原样保留。用户程序不停止、不重启、不执行。已加载任务才尝试不带 -w/-F 的 launchctl load 重复登记刷新显示，不加载原本未加载的任务。禁用/允许状态保持不变。新配置等待原子写入稳定后核对；陌生更新超出规则则跳过。

风险控制：规则与进度保存在用户私有运行目录，不上传。首次目标来源不可被第二次执行覆盖；拒绝自引用、符号链接配置、越界目录、源码变化、离线卷。逐次事务保存原入口字段和摘要，不复制配置中的参数或环境凭据。原子提交前重验字节、inode、目标和规则；失败不动当前配置。提供比对后恢复入口功能。界面区分自动完成、已核实、安全例外和待核查，历史事件不充当待办。

范围限制：本功能无法让任意第三方安装器提供真实用途；不能保证所有设置页面采用相同显示名。未知用途不自动执行。根服务须单独证据和权限，不创建宽泛提权守护进程。

交付：源码、自动巡检接入、规则登记命令、事务与复验测试、真实本地服务命名、后台自动执行验收、公开源码同步。保留现有 Swift 应用签名，不为更新 Python 逻辑重签主应用。
